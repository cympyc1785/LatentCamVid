# agent history — 세대 간 대조용 누적 기록

`.claude/agent-report-protocol.md` 의 **`history` 모드** 산출물이 여기 쌓인다 (`snapshot` 모드의 짝이다 — 저쪽은 현재 상태 하나, 이쪽은 시간에 걸친 누적).
한 줄 = 한 실행이고, **세대를 가로질러 비교**하기 위한 것이다 (예: d259 / d260 / d261 뱅크 감사를
나란히). main 이 경로와 키 집합을 프롬프트로 줬을 때만 쓰인다.

## 왜 `results/agent/` 가 아니라 여기인가

`results/` 는 gitignore 대상이다. history 는 "장기 기억" 이 존재 이유인데 거기 두면 디스크에만
남고 버전 관리가 안 된다 — 다른 머신에서 보면 없고, 언제 어떤 값이었는지 되짚을 수도 없다.
`.claude/` 는 추적되고, 이 레포 규약이 **"에이전트만 읽는 문서는 `.claude/` 아래 둔다"** 이므로
예외 규칙을 새로 만들지 않아도 된다.

`*.log` 는 gitignore 에 걸리므로 확장자는 **`.jsonl`** 을 쓴다.

## 규칙

- **JSONL 한 줄만 append.** 기존 줄을 고치거나 지우지 않는다.
- **한 줄 500 바이트 이내.** 서술이 아니라 수치만 넣는다.
- 키 집합은 main 이 정한다. agent 는 **키를 새로 만들지 않는다** — 열이 늘면 과거 줄과 대조가
  깨진다. 줄 게 없는 키는 `null`.
- **중복은 정상이다.** 같은 대상을 두 번 감사하면 줄이 둘 생기고, `generated` 가 늦은 줄이
  최신이다. 정리는 main 이 한다.
- history 를 썼어도 **snapshot 보고서(md)는 따로** 쓴다. 반환 JSON 의 `report` 는 항상 md 다.

## 파일 하나당 하나의 질문

이름은 **답하는 질문**으로 짓는다 (`bank_audit.jsonl`, `gate_binding.jsonl`). 한 파일에 서로
다른 성격의 행을 섞으면 키 집합이 늘어나 위 규칙이 깨진다.
