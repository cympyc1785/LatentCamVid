# agent 보고 규약 (단일 출처)

`.claude/agents/*.md` 전부가 이 파일을 참조한다. 규약을 고칠 일이 생기면 **여기만** 고친다 —
4개 정의에 복붙해 두면 그것부터 서로 어긋난다.

## 왜 파일로 보고하나

agent 의 반환 텍스트가 길면 main session 의 컨텍스트를 그만큼 먹고, 여러 agent 가 동시에
돌아오면 어느 결과가 무엇이었는지 섞인다. 그래서 **내용은 파일에, main 에는 신호만** 준다.

## 1. 반환값 — JSON 한 줄. 그 외엔 아무것도 출력하지 않는다

작업이 끝나면 최종 텍스트로 **이 한 줄만** 낸다. 앞뒤에 설명·인사·요약을 붙이지 않는다.

```json
{"status":"ok","role":"reader","report":"/절대/경로/report.md","lines":87,"bytes":5214,"headline":"d260 576행 중 clamped_low 252 (43.8%), binding obb 156/ground 59/approach 37"}
```

| 키 | 값 |
|---|---|
| `status` | `ok` 완수 / `partial` 일부만 / `failed` 못 함 |
| `role` | `reader` \| `critic` \| `executor` \| `writer` |
| `report` | 보고서 **절대 경로** |
| `lines` / `bytes` | 실제로 쓴 파일 크기 (예산 준수 증거) |
| `headline` | **120자 이내** 한 줄. 원본 수치 포함 |

`headline` 을 두는 이유: 이게 없으면 main 이 사소한 결과까지 매번 파일을 열어야 한다. 대신
**120자를 넘기지 않는다** — 넘길 내용이면 그건 보고서에 들어갈 것이다.

`status: failed` 여도 **보고서 파일은 쓴다.** 왜 실패했는지가 거기 들어간다.

## 2. 보고서 경로 — main 이 지정한다. 스스로 정하지 않는다

호출 프롬프트에 경로가 있으면 **그 경로에만** 쓴다. 없으면 아래 기본값을 쓰고 `headline` 에
"경로 미지정" 이라고 적는다.

```
/data1/cympyc1785/LatentCamVid/tmp/agent/<role>.md
```

- **절대 경로로 쓴다.** agent 마다 cwd 가 다를 수 있다 (repo 루트 / CinemaTraj / latentcam).
- 없으면 `mkdir -p` 로 상위 폴더를 만든다.
- **지정된 파일 하나만 쓴다.** 부수 파일(중간 결과·캐시·plot)을 남기지 않는다.

## 3. 두 가지 모드

### snapshot (기본) — 싱글톤, 통째로 덮어쓴다

**현재 상태만** 남긴다. `Write` 로 **전체를 새로 쓴다** — `Edit` 로 덧붙이지 않는다.
이전 실행의 내용은 사라지는 게 맞다. "이번 조사의 답"이 파일의 전부다.

같은 role 을 병렬로 여러 개 띄울 때는 **main 이 서로 다른 경로를 준다**
(`tmp/agent/reader-d259.md`, `reader-d260.md` …). 경로가 겹치면 서로 덮어쓴다 — 그건 main 의
책임이고, agent 는 받은 경로를 의심하지 않는다.

### history (opt-in) — 세대 간 대조가 필요할 때만

`snapshot` 이 **현재 상태 하나**라면 이쪽은 **시간에 걸친 누적**이다. 둘은 짝이고 용도가 다르다.

main 이 **명시적으로 history 경로를 줬을 때만** 쓴다. 한 줄 = 한 실행이고, 나중에 세대를
가로질러 비교하기 위한 것이다 (예: d259 / d260 / d261 뱅크 감사를 나란히).

```
/data1/cympyc1785/LatentCamVid/.claude/history/<name>.jsonl
```

`results/` 가 아니라 `.claude/` 인 이유: `results/` 는 gitignore 대상이라 history 가 디스크에만
남고 버전 관리가 안 된다 — "장기 기억" 이 존재 이유인데 그러면 다른 머신에서 보이지도, 언제
어떤 값이었는지 되짚지도 못한다. `.claude/` 는 추적되고 **"에이전트만 읽는 문서는 `.claude/`
아래"** 규약에도 맞는다. 확장자는 **`.jsonl`** 이다 (`*.log` 는 gitignore 에 걸린다).
파일 이름은 **답하는 질문**으로 짓는다 (`bank_audit.jsonl`) — 한 파일에 성격이 다른 행을 섞으면
키 집합이 늘어 아래 규칙이 깨진다.

- **JSONL 한 줄만 append.** 기존 줄을 고치거나 지우지 않는다.
- **한 줄 500 바이트 이내.** 서술을 넣지 말고 수치만 넣는다.
- 키 집합은 main 이 프롬프트에 준다. **키를 새로 만들지 않는다** — 열이 늘면 과거 줄과 대조가
  깨진다. 줄 게 없는 키는 `null` 로 둔다.
- **중복을 신경 쓰지 않는다.** 같은 대상을 두 번 감사하면 줄이 둘 생기는 게 맞다 —
  `generated` 가 늦은 줄이 최신이고, 정리는 main 이 한다. 기존 줄을 찾아 고치려 들지 않는다.
- history 를 썼어도 **snapshot 보고서는 따로 쓴다.** `report` 는 항상 md 를 가리킨다.

## 4. 보고서 형식 — 섹션을 새로 만들지 않는다

frontmatter + 정해진 섹션만. 순서도 고정이다. **빈 섹션은 `(없음)` 으로 남긴다** — 빼지 않는다.
섹션을 추가하고 싶어지면 그건 예산을 넘겼다는 신호다.

```markdown
---
protocol: 1
role: reader
task: <main 이 준 지시 한 줄 그대로>
status: ok
mode: snapshot
generated: 2026-09-23T12:34:56+09:00
source: <읽은 것의 범위 — 예 "out/*/hole_bank_d260/bank.csv 16편 576행">
source_rev:                       # 코드·구조를 요약했으면 필수, 데이터 집계만 했으면 null
  - fit_hole_ladder.py@6844dee
  - presets.py@a9c390a
---

## 결론
<3줄 이내. 수치를 포함한 답. 서론 금지>

## 표
<수치. 각 표에 n 을 적는다. 표가 없으면 (없음)>

## 근거
<file:line 인용 또는 집계 경로. 8개 이내>

## 한계
<확인하지 못한 것, 가정, 표본이 부족한 곳. 5줄 이내>
```

`source_rev` 는 **이 보고서를 캐시로 쓸 수 있게 하는 키**다. 코드나 구조를 요약한 보고서는
다음에 같은 질문이 왔을 때 **소스를 다시 읽지 않기 위해** 재사용된다 — 그러려면 "그 사이에
소스가 바뀌었나"를 싸게 판정할 수 있어야 한다. 요약한 파일마다 이렇게 찍는다.

```bash
git log -1 --format=%h -- <파일>          # 리비전
git status --porcelain -- <파일>          # 비어 있지 않으면 미커밋 변경이 있다
```

**미커밋 변경이 있으면 리비전 대신 `dirty` 를 적는다** — 이 레포는 고치고 나중에 커밋하므로,
해시만 믿으면 방금 바꾼 코드를 안 바뀐 것으로 읽는다.

캐시를 **쓰는 쪽**(다음 reader)의 규칙: 보고서의 `source_rev` 와 지금 값을 비교해 **전부 같으면
소스를 읽지 않고 보고서를 신뢰한다.** 하나라도 다르거나 `dirty` 면 그 파일만 다시 읽는다.
데이터 집계만 한 보고서는 `null` 로 두고, 캐시로 쓰지 않는다 (데이터는 언제든 다시 구워진다).

`protocol` 은 **이 파일의 판 번호**다. 지금은 `1` 이다. 형식이 바뀌면 여기가 올라가고, main 은
그 값으로 `tmp/agent/` 에 남은 보고서가 **낡은 판인지** 한 줄로 가른다. 값을 빼지 않는다.

`generated` 는 `date -Iseconds` 로 찍는다. `task` 를 그대로 싣는 이유: main 이 나중에 이 파일을
읽을 때 **다른 작업의 낡은 스냅샷인지** 한 줄로 판별해야 한다.

## 5. 예산 — 쓰기 전에 확인한다

| 항목 | 상한 |
|---|---|
| 파일 전체 | **120줄 / 8 KB** |
| `## 결론` | 3줄 |
| 표 | 표 3개까지, 각 20행까지 |
| `## 근거` | 8개 |
| `## 한계` | 5줄 |
| 코드·로그 인용 블록 | 2개까지, 각 10줄 |
| `headline` | 120자 |

넘으면 **자르고 잘랐다고 적는다.** 조용히 줄이지 않는다.

```
… 그 외 34행 생략 (전체 54행, 상위 20행만)
```

무엇을 남길지 우선순위: **판정을 뒤집을 수 있는 수치 > 이상치 > 대표값 > 나머지.**

## 6. 내용 규약

- **파일 내용을 통째로 붙여넣지 않는다.** 결정적인 몇 줄만 인용한다.
- **실험 수치를 임의로 요약하지 않는다.** 원본 그대로 옮긴다. 반올림 금지.
  "대체로 개선" 같은 표현 금지 — `141 -> 262 (24.5% -> 45.5%)` 로 쓴다.
- **표본 수 n 을 항상 적는다.** 비율만 적으면 검증이 안 된다.
- 학습 수치의 원본은 **wandb** 다. stdout 에서 주웠으면 그렇게 밝힌다.
- **못 찾은 것은 "없다"가 아니라 "찾지 못했다"** 로 쓴다.
- 확신이 없으면 `## 한계` 에 적는다. 추측을 사실처럼 쓰지 않는다.

## 7. 정리는 main 이 한다

- agent 는 **파일을 지우지 않는다.** 낡은 보고서가 보여도 건드리지 않는다.
- `tmp/agent/` 가 쌓이면 main 이 정리한다. 삭제는 목록·근거를 보고하고 승인을 받는다.
- 보고서를 `results/` 나 `DECISIONS.md` / `CHANGELOG.md` 로 **승격하는 것도 main 이 한다.**
  agent 는 그 파일들을 건드리지 않는다.
